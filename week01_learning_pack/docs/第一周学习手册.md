### 3.2 课件要点

**张量的四个最先检查项。** `shape` 是每个轴的长度；`dtype` 是数值类型；`device` 是计算设备；`requires_grad` 决定相关运算是否需要追踪梯度。本周数值特征和回归目标使用 `float32`，设备固定 CPU。[R3][R4]

**先写形状，再写运算。** 本练习将 `X:[B,D]` 约定为 B 条样本、每条 D 个特征。手写仿射变换使用 `W:[D,K]`、`b:[K]`，输出 `[B,K]`。矩阵乘法 `@` 会沿匹配的特征维求和；`*` 是逐元素相乘，不能互换。

```python
X = torch.tensor([[1.0, 2.0], [3.0, 4.0]])  # [2,2]
W = torch.tensor([[2.0], [-3.0]])             # [2,1]
b = torch.tensor([0.5])                      # [1]
pred = X @ W + b                            # [2,1]
# 第一行：1*2 + 2*(-3) + 0.5 = -3.5
# 第二行：3*2 + 4*(-3) + 0.5 = -5.5
```

**切片要考虑轴是否保留。** 对 `[B,D]`，`X[:, -1]` 得到 `[B]`，`X[:, -1:]` 得到 `[B,1]`。预测 `[B,1]` 与标签 `[B]` 相减，可能被广播成 `[B,B]`。因此，本周先显式检查预测与目标形状完全相同。

**MSE：把每条预测的误差汇总成标量。** 本周每条样本只有一个输出，定义 `L = mean((pred-target)^2)`。它是当前回归任务的损失，不是后续语言模型默认使用的损失。

## 4. 第2次课：先手算，再验证自动求导

**要回答的问题：** 一个损失数字如何变成每个参数的更新方向？

**阅读：** Raschka A.3—A.4；PyTorch 自动求导。链式法则仍不清楚时，选看 Karpathy 第一讲。[R1][R4][R9]

### 4.1 课堂安排

| 环节 | 建议投入 | 本次具体动作 |
|---|---:|---|
| 阅读与概念 | 20分钟 | 画出 `w,x,b → pred → error → loss`。 |
| 纸面推导 | 20分钟 | 独立算出下面例子的 loss、dw、db。 |
| 代码实验 | 60分钟 | 补 TODO 5—7；反向前后分别打印参数和梯度。 |
| 测试与复述 | 20分钟 | 通过5项测试；解释梯度累积的 2、4、2。 |

### 4.2 可手算的完整例子

设 `x=2`、`y=5`、`w=1`、`b=0`：

```text
pred = w*x+b = 2
error = pred-y = -3
L = error² = 9

dL/dpred = 2*error = -6
dpred/dw = x = 2      → dL/dw = -12
dpred/db = 1          → dL/db = -6
```

如果用学习率 `0.1` 手动做一次普通梯度下降：

```text
w_new = 1 - 0.1*(-12) = 2.2
b_new = 0 - 0.1*(-6)  = 0.6
```

这个特定单样本例子更新后预测为 5。**这来自本例的数值选择，不表示任意模型更新一步都能拟合数据。**

### 4.3 必须分清的三件事

`requires_grad=True` 让相关参数参与梯度计算；`loss.backward()` 把梯度累积到参数 `.grad`；只有后续显式优化步骤才更新参数。自动求导不是自动选择学习率，也不是自动完成训练。[R4][R5]

每一步训练通常重新执行前向，得到新的计算图。梯度却会保留并累积，因此通常要清零。`accumulation_demo()` 的三次前向都是新图，预期梯度依次为 2、4、2；不能为解决这里的问题而滥加 `retain_graph=True`。[R7]

对更新前参数做比较时，用 `p.detach().clone()` 保存独立快照。直接 `old=p` 会引用同一参数，无法真实记录“之前”。

### 5.3 代码结构

```python
model.train()
optimizer.zero_grad(set_to_none=True)
pred = model(x)
loss = mse(pred, y)
loss.backward()
optimizer.step()
```

`nn.Module` 管理模型参数；`nn.Linear(2,1)` 接收最后一维为2的输入，输出一个数。它的权重存为 `[1,2]`，与第1次手写 `W:[2,1]` 相比，使用了转置的存放约定。[R1]

本练习的 `train_step()` 额外保存参数快照、检查 loss 和梯度是否有限，并记录梯度范数及参数变化。检查这些数值，是为了防止“loss 算出来了，但根本没有更新”的假训练。

`evaluate()` 使用 eval 模式和 no_grad，不调用更新。第一周这个函数计算的仍是同一 batch 上的拟合误差，**函数名叫 evaluate 也不会自动让它变成独立测试集评价**。

### 5.4 日志字段怎么读

| 字段 | 意思 |
|---|---|
| `step` | 已进行的第几次更新。 |
| `loss_before` | 当前步更新前、在固定 batch 上计算的 MSE。 |
| `loss_after` | 当前步更新后重新前向的 MSE。 |
| `grad_norm` | 当前步所有参数梯度的整体 L2 范数。 |
| `parameter_delta` | 本次更新前后参数差异的整体 L2 范数。 |

早期应能观察到非零梯度和非零参数变化。不要强求每个参数在每一步都变化；接近数值精度极限时，极小更新可能被舍入。[本包实验]

### 6.2 保存加载的正确边界

保存：`torch.save(model.state_dict(), path)`。加载：先创建新的同结构模型，再用 `torch.load(path, map_location="cpu", weights_only=True)` 取得权重字典并严格加载。只加载自己生成或可信来源的文件。[R6]

`model.eval()` 与 `torch.no_grad()` 解决不同问题。前者改变某些层的模式，后者不记录用于反向的图。本周线性模型没有 Dropout/BatchNorm，因此 eval 不改变它的计算公式，但我们仍练习两者一起使用。[R4][R6]

这一课只保存模型权重，**不等于完成恢复训练**。优化器状态、调度器、随机状态和数据位置在第5周再统一处理。[R8]

## 7. 问题与参考解答

每次课先尝试口述本课6道题，再看参考解答。前半句说概念，后半句用本次实验举例，避免只背 API 名称。

### Q01｜张量与 Python 列表有什么区别？

**所属课次：第1次课。**

**参考解答：** 本周把张量理解为带形状、数据类型和设备信息的多维数值容器。列表是 Python 的通用容器；张量可以批量执行矩阵运算，符合求导条件时还能参与 autograd。不要只看打印出来的数字，应同时检查 shape、dtype、device。[R3]

### Q02｜shape、ndim、numel 分别表示什么？

**所属课次：第1次课。**

**参考解答：** 对形状 [3,4] 的张量，shape 是两个轴的长度，ndim=2 表示有两个轴，numel=12 表示元素总数。它们都不直接告诉你每个轴的业务含义；[B,D] 里的 B 和 D 是我们约定的样本数与特征数。

### Q03｜为什么 x[:, -1] 和 x[:, -1:] 不一样？

**所属课次：第1次课。**

**参考解答：** 前者用整数索引最后一列，结果通常为 [B]；后者用范围切片，保留列轴，结果为 [B,1]。训练前应先确认目标形状，而不是等 loss 异常才检查。本练习要求预测与目标都为 [B,1]。[R3]

### Q04｜X:[8,2]，W:[2,1]，b:[1]，X@W+b 是什么形状？

**所属课次：第1次课。**

**参考解答：** X@W 的内维 2 匹配，输出为 [8,1]；b 的单个值沿样本轴广播，结果仍为 [8,1]。矩阵乘法会对特征轴求和；逐元素乘法 * 不会做同样的求和。

### Q05｜预测 [32,1]、目标 [32]，为什么不能直接相减？

**所属课次：第1次课。**

**参考解答：** 按广播规则，两者相减可以得到 [32,32]：原本想计算每条样本自己的误差，却变成两两比较。程序可能仍得到一个标量 loss，因此不报错不等于语义正确。本练习先检查两者形状完全一致，错误形状直接抛 ValueError。

### Q06｜CUDA available=False 是不是环境失败？

**所属课次：第1次课。**

**参考解答：** 不是。本周训练固定使用 CPU。只要 torch 能导入、CPU 运算与梯度测试通过，就可以继续。CUDA 的可用性是额外设备信息，不是第一周的通关条件。[R2]

### Q07｜requires_grad=True 和 .grad 各是什么？

**所属课次：第2次课。**

**参考解答：** requires_grad=True 让浮点参数参与可追踪的求导计算；对本练习的叶子参数调用反向传播后，.grad 用于保存累积的梯度。一般中间张量的 .grad 不会自动保留，不能看到 None 就认定整张图没有梯度。[R4]

### Q08｜手算例子里 loss、dw、db 是多少？

**所属课次：第2次课。**

**参考解答：** x=2、y=5、w=1、b=0。预测 wx+b=2，误差 e=-3，平方损失 L=9。由链式法则，dL/dw=2e*x=-12，dL/db=2e=-6。代码必须用 autograd 得到这些值，不能把答案写死。

### Q09｜loss.backward() 会修改 w 和 b 吗？

**所属课次：第2次课。**

**参考解答：** 在本练习中不会。它计算并累积参数梯度，w 仍为 1、b 仍为 0。随后 optimizer.step() 才根据梯度和学习率更新参数。我们分别用测试检查“梯度存在”和“参数变化”。[R4][R5]

### Q10｜为什么不清梯度会得到 2、4，而不是两次都是 2？

**所属课次：第2次课。**

**参考解答：** 对 w=1，每次重新计算 w² 的梯度都是 2，但 backward 默认把新梯度加到已有 .grad。第一次为 2，第二次为 4；第三次先设 w.grad=None，再重新前向与反向，就回到 2。这里每次是新计算图，不需要 retain_graph=True。[R7]

### Q11｜为什么手动更新参数常放在 torch.no_grad() 中？

**所属课次：第2次课。**

**参考解答：** 我们把参数更新视为优化动作，而不是下一步要继续求导的模型前向过程。no_grad 避免为这个动作建立普通反向图，也避免直接原地修改需梯度叶子参数的常见报错。调用标准 optimizer.step() 时通常不用再自己包一层。[R4][R5]

### Q12｜为什么记录 old=model.weight 不可靠？

**所属课次：第2次课。**

**参考解答：** 这只是给同一个张量另起一个名字，后续原地更新也会反映在 old 上。要保存更新前的独立数值快照，使用 model.weight.detach().clone()。detach 断开求导关系，但单独 detach 仍可能共享存储；clone 才复制数值。

### Q13｜nn.Linear(2,1) 为什么只有 3 个参数？

**所属课次：第3次课。**

**参考解答：** 一个输出对两个输入特征各有一个权重，再加一个偏置，所以 2×1+1=3。PyTorch 该层的 weight 形状为 [1,2]，计算相当于 X @ weight.T + bias；第1次课手写 affine 约定 W 为 [2,1]，只是存放方向不同。[R1]

### Q14｜backward、step、zero_grad 的区别是什么？

**所属课次：第3次课。**

**参考解答：** backward 算梯度，step 用优化器更新参数，zero_grad 清掉旧梯度。常规单 batch 更新采用“清梯度→前向→loss→反向→更新”。梯度累积是有意延后清零和更新的另一种安排，本周先不混用。[R5][R7]

### Q15｜learning rate=0 会出现什么？

**所属课次：第3次课。**

**参考解答：** 梯度仍然可以被正常计算，但本练习使用无动量、无权重衰减的 SGD，更新量为 -lr*grad，因此参数不变；相同输入上的 loss 也不变。它是“反向不等于更新”的对照实验，不是新的学习方法。

### Q16｜为什么 loss 不一定每一步都下降？

**所属课次：第3次课。**

**参考解答：** 不同 batch、随机层或过大的更新都可能让下一次损失更大；大多数训练没有逐步单调下降的保证。本练习是固定 batch、简单线性模型和小步长，先用这个受控环境检查实现。判断较复杂训练时，应结合固定评价条件和整体趋势。

### Q17｜同一个 batch 的 loss 很低，说明泛化好吗？

**所属课次：第3次课。**

**参考解答：** 不能。这只说明该模型和训练过程能够拟合这些训练样本。第一周故意重复同一 batch，是为了排除数据管线变化、验证训练代码；要评价未见样本效果，后续需要独立数据和合适的评价设计。

### Q18｜训练后期梯度非零但 parameter_delta=0，一定是 bug 吗？

**所属课次：第3次课。**

**参考解答：** 不一定。有限精度下，非常小的更新可能被舍入掉。本练习参考运行最后几步就可能出现这一现象。优先确认早期步骤有真实更新、loss 显著下降；不要要求所有参数、每个训练步骤都必须发生可见变化。

### Q19｜model.eval() 与 torch.no_grad() 有什么区别？

**所属课次：第4次课。**

**参考解答：** eval 切换模型模式，影响 Dropout、BatchNorm 等依赖训练模式的层；no_grad 控制是否建立用于反向的计算图。eval 不会自动关闭 autograd，no_grad 也不会自动把模型切到 eval。本周回归模型没有 Dropout/BatchNorm，两种模式的前向公式相同，但仍练习规范调用。[R4][R6]

### Q20｜state_dict 保存了网络结构吗？

**所属课次：第4次课。**

**参考解答：** 没有保存可直接替代模型类定义的完整结构。它主要保存参数和注册缓冲区。本周加载时先创建同样的 TinyRegressor，再严格加载 state_dict；如果结构或维度不同，不能假设权重可以直接装进去。[R6][R8]

### Q21｜为什么 torch.load 使用 weights_only=True 和 map_location="cpu"？

**所属课次：第4次课。**

**参考解答：** weights_only=True 限制加载时可反序列化的对象种类，是本练习加载权重的明确设置；map_location="cpu" 把张量映射到 CPU。它们不代表任意来源的文件都安全，只加载自己生成或可信来源的模型文件。[R6]

### Q22｜保存再加载后，如何验证没有出问题？

**所属课次：第4次课。**

**参考解答：** 使用相同模型结构、同一输入、同样的 eval 模式，在 no_grad 下分别得到预测；用 torch.testing.assert_close 比较容差，并记录 max_abs_diff。再检查权重键名、设备和形状。不要只以“加载没有报错”作为依据。

### Q23｜只保存 state_dict 能从原状态继续训练吗？

**所属课次：第4次课。**

**参考解答：** 可以恢复权重并重新开始训练，但一般不能保证恢复原训练轨迹。完整续训还要考虑优化器状态、步数、学习率调度、随机状态和数据读取位置。第一周只验收权重恢复与预测一致；完整检查点在第5周实现。[R8]

### Q24｜这个回归模型与大模型有什么关系？

**所属课次：第4次课。**

**参考解答：** 它不是语言模型，也没有注意力或分词器。本周复用的是训练的基本结构：输入张量→可训练模型→损失→反向→参数更新→保存加载。后续改变输入表示、网络结构和损失，但你仍要检查同样的梯度、参数、模式与恢复问题。
